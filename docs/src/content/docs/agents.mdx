---
title: Pages for agents
description: Your pages as Markdown an agent reads whole, with llms.txt to find them, in the site and in your package.
---

An agent reads a page's source, not its rendering: an MDX page's imports, its
components, and an example shown from a file it imports are noise to it, and
the example itself is missing. `agents` writes each page as plain Markdown, the
way an agent reads it, and an index of them all,
[`llms.txt`](https://llmstxt.org).

Every site built on the theme has them, beside its pages: `<base>/llms.txt`
and `<base>/<page>.md`. They change nothing a person reads; `agents: false`
leaves them out.

## What a page becomes

Each page is `# <title>`, its `description` as the first paragraph, then its
body, with:

- its `import` and `export` lines left out;
- every component given `code=` a file the page imports `?raw`, Starlight's
  `<Code code={x} />` or a component of your own, as a fenced block of that
  file, its language the component's `lang` or the file's extension, its
  `title` the fence's; and given text, or a constant of the page's built of
  text and the fields of a JSON file it imports, as an install line built of
  the package's version is, as a fenced block of that text;
- a component's other files, given as `{ "name.css": css }`, each a fenced
  block titled by its name;
- what renders only in a browser left out: a live demo inside such a
  component, a block marked `not-content`, an inline component with no text;
- any other component flattened to its text, under its `title` or `label`
  where it has one: a tab, a card;
- Starlight's asides, `:::note`, as they are written.

A `?raw` import is found as Vite finds it: through `vite.resolve.alias` in your
`astro.config.mjs`, or by a path from the page. A file that is not there stops
the build; code given by anything else is left out with a warning naming the
page.

A link to another page goes to that page's Markdown, and a link to the site
elsewhere, odoc's reference say, to the site itself.

## In the site

`astro build` writes `llms.txt` at the site's root and each page beside its own
directory, `guide/routes.md` for `/guide/routes/`, every link absolute from
your `site`. `llms.txt` is your title, your `description` as its summary, then
the sidebar's groups, a page a line, its description after it:

```md title="llms.txt"
# widgets

> Widgets for everyone.

## Guides

- [Routes](https://acme.dev/widgets/guide/routes.md): A route, its method and its path.
```

A nested group is listed in the group it is in, and a page the sidebar leaves
out under `## Other pages`.

## In your package

An agent working offline reads what is installed. Give `dir`, a folder from the
Astro root, and the build writes `llms.txt`, `pages/<page>.md` and a skill into
it too, every link relative, for your repository to commit and your package to
install:

```js
starlightThemeHypha({
  agents: {
    dir: "../agents",
    preamble: readFileSync(new URL("./agents.md", import.meta.url), "utf-8"),
    groups: { Reference: "Each module's `.mli` is its contract." },
  },
});
```

`preamble` is Markdown after `llms.txt`'s summary and before the groups, for
what an agent should know before any page, and `groups` is Markdown under a
group's heading, by its label.

With dune, the folder's files go into the package's documentation, beside its
README, `$(opam var widgets:doc)/llms.txt` and the rest:

```lisp
(install
 (package widgets)
 (section doc)
 (source_trees (agents as .)))
```

## The skill

An agent reads the docs only if something tells it to. With `dir`, the build
also writes `skills/<name>/SKILL.md`, a skill in the
[Agent Skills](https://agentskills.io) format, which a user copies into
`.agents/skills/` or `.claude/skills/`. It holds no page: it says when to read
them, before writing code with the library; where, the catalogue installed
with the release the code builds against, `$(opam var <package>:doc)/llms.txt`,
the site's only where none is installed; and to build from the parts the
pages give, writing by hand only what none does.

```js
starlightThemeHypha({
  agents: {
    dir: "../agents",
    skill: {
      name: "widgets", // the site's title, lower case and dashed, unless given
      package: "widgets", // the opam package the folder is installed with; the name, unless given
      description: "Use before writing or changing OCaml code that uses widgets.", // the default, with your description
      before: "writing code with widgets", // ends the skill's "Read it before …"; the default
      instead: ["a raw `<button>`, where `Widgets.Button` is one"],
    },
  },
});
```

`instead` is what is easily written by hand where the library has a part,
listed under the steps for an agent to look for the part first. `before`
says what the agent is about to do, for a library used otherwise than by
writing code with it -- a linter's findings, say.
`skill: false` writes none.

## Keeping it current

The folder is generated, so a check regenerates it and compares. `astro sync`
reads the pages without building the site, and `HYPHA_AGENTS` asks it to write
the folder or to check it:

```console
$ HYPHA_AGENTS=write bunx astro sync
$ HYPHA_AGENTS=check bunx astro sync
```

The check fails on any file that is changed, missing or no longer generated,
the skill's among them, and names each, so a page changed without the folder
fails your CI.
